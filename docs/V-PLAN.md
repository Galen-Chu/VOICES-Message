# VOICES-Message(聲管庫)產品規劃

2026-10-14 立項(repo 建立、V-PLAN v1)。與 TEXT-Message(文管庫)、MEDIA-Message(媒管庫)為**家族第三條產品線**:文管庫文字為主、媒管庫媒體為主,本產品**聲音為主、文字是講稿**。

> 立項背景:媒管庫 M-PLAN §5 遠期「聲音線」原待媒管庫完成後再議產品名;2026-10-14 維護者定案**另立 repo 獨立開發**(VOICES-Message),與兩庫並行不互阻塞。

## 1. 平台現實與內容形態(沿用 2026-09-23 查證,動手前依串接紀律複查)

| 分發途徑 | 可行性 | 前置 |
| --- | --- | --- |
| 社群平台直傳音檔 | ❌ **無主流平台支援**(FB/IG/Threads/YouTube 皆不收純音檔) | — |
| 瀏覽器錄音 → 下載檔 | ✅ 零後端(MediaRecorder API) | 無 |
| 音轉影片(波形+封面)→ 社群 | ✅ 走媒管庫既有發佈線(影片) | 家族 handoff 契約 |
| Podcast RSS 託管 | ⚠️ 需音檔公開 URL(Firstory/SoundOn 或自建) | **觸發後端決策**(與「媒體絕不過後端」紅線定案綁一起) |

**內容形態定調(D2)**:短語音+講稿優先(社群可分發性最高、且零後端即可完成);podcast 節目線屬遠期。

## 2. 核心迴圈與紅線

**迴圈**:錄音(或匯入音檔)→ 整理(標題/說明/講稿)→ 分發(下載/音轉影片交媒管庫)→ 記錄(僅 metadata)。

**紅線(整套沿用家族體系)**:

- **音檔僅存瀏覽器記憶體,絕不落地、絕不經後端**;落地僅 metadata(檔名/類型/時長/大小/說明);
- token / AI key 比照家族:key 僅存使用者瀏覽器(BYOK);本產品 V0–V3 設計**零後端**;
- 未設定對應環境的建置=降級模式,建置不得失敗。

## 3. 決策記錄(D1–D7,2026-10-14 隨立項暫行定案;任一項動工前維護者可推翻,改動即更新本節)

- **D1 產品定位**:VOICES-Message(聲管庫)——聲音為主、文字是講稿;家族分工=文管庫(文字)/媒管庫(媒體)/聲管庫(聲音),路線圖互不綁架。
- **D2 內容形態**:短語音+講稿優先;podcast 託管為遠期(§1)。
- **D3 分發策略**:一期下載檔(零後端);二期音轉影片交媒管庫(family handoff);podcast RSS 遠期。
- **D4 一期(V1)=純瀏覽器錄音機**:MediaRecorder 錄/停/播放/下載;格式探測適配 Chrome(webm)/Safari(mp4);錄音記錄僅 metadata 落地。
- **D5 音檔紅線**:絕不落地、絕不經後端(§2)。
- **D6 AI 候選(V2,待維護者拍板)**:Gemini BYOK 音訊輸入——逐字稿、摘要、講稿生成(瀏覽器直呼,零後端);金鑰沿用家族共用慣例(唯讀文管庫 `text-message:gemini-key`,見文管庫 CLAUDE.md IA-D8)。
- **D7 技術骨架**:同家族(文管庫 2026-10-06 升級後版本:React 19 / Vite 8 / TS 7 / Vitest 5);設計系統與 CI/Pages 管線自文管庫複製;共用元件複製、不 monorepo;`family:*` 契約鍵同規(不互讀對方內部鍵)。

## 4. 分期

- **V0(✅ 2026-10-14)**:repo 與文件(V-PLAN/README/CLAUDE/LICENSE)、骨架(可建置可測試可部署)、設計系統、首批純邏輯:`src/utils/audioKind.ts`(音檔類型偵測)+ `src/utils/recorderMime.ts`(錄音格式探測)+ 測試;CI(test→contrast→build→E2E)與 Pages 部署管線。
- **V1 瀏覽器錄音機**:MediaRecorder 錄音(暫停/續錄)、播放、下載(依格式給副檔名)、錄音列表(僅 metadata,localStorage `voices-message:v1`);麥克風權限與不支援環境的誠實降級。
- **V2 講稿與 AI(候選,待拍板)**:講稿編輯(錄前大綱/錄後逐字稿);Gemini BYOK 音訊輸入(逐字稿/摘要/講稿生成);family handoff——講稿送文管庫(caption 工作流)。
- **V3 音轉影片分發**:canvas 波形+封面圖合成影片(純前端),交媒管庫發佈(family handoff 檔案或重選)。
- **遠期 Podcast RSS**:音檔託管(Firstory/SoundOn API 或自建 R2)→ 觸發後端決策,與媒管庫 M3 圖床共用同一個「後端資料邊界」大定案,不逐案判。

## 5. 與家族的整合(沿用文管庫 `docs/IA-PLAN.md` §3.2 契約)

- 兩站同源(`galen-chu.github.io`)→ localStorage 與配額共用;跨產品一律走版本化 `family:*` 契約鍵,**不互讀對方內部鍵**(`text-message:v2` / `media-message:v1` / 本產品 `voices-message:v1`);
- 唯一例外沿用 IA-D8:媒管庫/本產品可唯讀文管庫 Gemini 金鑰(使用當下才讀、永不寫入);
- V2/V3 的 handoff 實作時,於本檔補充對應契約鍵定義(與兩庫協調後)。

## 6. 邊界備忘

- 文管庫=文字工作流、媒管庫=媒體發佈、本產品=聲音內容;**音轉影片的「影片發佈」屬媒管庫**,本產品只產出影片檔並交接;
- 三 repo 各自部署、各自路線圖;家族契約變更須三庫同步協調。
